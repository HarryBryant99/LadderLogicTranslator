Getting the BMC results out of the old verifier (which uses z3) is a 2 step process. The second step uses fan's computer. First, generate the tptp files on the desktop (on Pragun's desk) using clausegen but the actual BMC run in z3 needs access to fan's system as other systems throw a memory error and the computation fails.

Step 1: 
- Generate the BMC tptp files using the function GenerateTptpFiles() from the IC3 codebase.
- Make sure you tweak the filepaths and create directories beforehand.

Step 2: 
- IMPORTANT: Copy Ladder.tptp from the clausegen run into the output directory in the same level as of the safety files.
- zip the output directory, and copy it over to fan's computer.
- change the <csv_file> value in the shell script (process_bmc_tptp.sh) as required. 
- a copy of the shell script is in the other-resources directory of this zip.
- unzip the output directory.
- assuming you are in the correct directory location, run: ./process_bmc_tptp.sh <unzipped_dir_name>
- you should see a csv file output (as defined in process_bmc_tptp.sh) with the BMC test results.

Note 1: for step 2, makes sure you use tmux to ssh into fan's computer (or any alternatives likes remote desktop) because the BMC test run typically takes hours to run and the ssh connection should not be terminated.

Note 2: Some tptp files generated by Pragun are stored in E Drive of the LL-Verifier system stored as tptp-files-gen-by-pragun. A copy is also included in the other-resources directory for convenience. 

Note 3: One can always regenerate the tptp files using the function GenerateTptpFiles()but the generation of tptp safety files takes some time. If you only need the ladder, run a simple inductive verification test inside the directory clausegen-exe-by-harry directory. The commands to run the tests are mentioned in the directory (commands.txt) as well as in the function that generates tptp files (ExecuteClausegenInCmd() in RunForSiemensTestbed.cs).

Step 3:
- After running the LadderLogicTranslator the generated files will be in the results folder. They will be in the folder named afer the Ladder (e.g. LevelCrossing), then in a sub folder named after the Ladder_Safety Property so that if they are mutliple properties generated they are all stored separately (e.g. results/LevelCrossing/LevelCrossing_p1)
- In each folder you will find the .aag file, the detailed aiger file, and the smt files for z3.
- Run "combine_aag" with the .aag file as a parameter and it will build a .aig file for ABC with the numbering key built in. For ABC you need to run the "make" command and it can be found here https://github.com/berkeley-abc/abc. Place inside the main LadderLogicTranslator/abc.
- Run "ic3_invariant" with Ladder_Safety Property will run ABC, produce the invariant and append it to the step case smt file.
